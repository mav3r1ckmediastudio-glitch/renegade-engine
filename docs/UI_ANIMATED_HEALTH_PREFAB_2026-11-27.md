## Creator workflow

Elements > Gameplay > Animated vial inserts one selected hierarchy. The root owns placement and size, Liquid is a Progress child, and Glass and metal is a separate Image child. Select the root and choose Edit vial. The shared native Studio modal offers a colour picker, Health/Mana/Strength presets, current and optional maximum attribute names, animated surface/bubbles, wave height, bubble count, optional decrease/increase sounds and a transient Preview fill slider. Save applies one authoring operation; Cancel discards the modal draft and resets its renderer preview. Ordinary Screen history handles Undo/Redo.

Health, Mana and Strength are configurable attribute bindings, not newly implemented gameplay systems. A missing maximum means a direct 0..1 value. The presets use possessed-player sources; custom existing source scope/target is retained when editing attributes. Cross-project adoption explicitly unassigns gameplay slots. Choose the appropriate preset or attributes for the receiving project. A preview value changes renderer presentation only and never saves simulated health or mana.

Select the whole vial root, then Elements > Reusable > Save selected as UI prefab. Saved UI prefabs lists the personal library and can also import a package manifest from disk. Insertion gives every widget fresh identity and destination-owned artwork and sounds, in one Undo step. Effective inherited styling is baked when publishing. Compact package resource names prevent imported directory paths growing on each save/reinsert. Stock presets have no sound; the pack has generic UI cues rather than a dedicated vial cue.

## Ownership and rendering

EngineBridge owns optional schema-3 ScreenLiquid metadata, strict numeric/path validation, atomic authoring, typed mask/audio dependencies and portable remapping. Existing progress frame/fill dependencies and remapping were corrected in prerequisite 80449c9. ScreenPrefabService publishes one hierarchy using the existing hashed portable Screen package, without introducing another document format. Studio owns interaction and private audition. ScreenRenderer owns an independent mask, output texture, animation clock and optional sound voice for each liquid instance; Studio and Runtime share that implementation.

The GPU produces a masked, bottom-up liquid surface and moving bubbles on a 24 fps / four-second loop, driven by the actual resolved fraction. It uses the supplied artwork's interior bounds. The supplied precomposited motion frames deliberately fill and empty the bottle themselves; playing them unchanged would contradict real health. The native effect therefore recreates the surface/bubble behaviour procedurally while keeping the supplied glass artwork untouched. Liquid tint affects only the liquid child. Reduced motion freezes animation while still responding to value changes. The original image and mask remain editable resources through ordinary Screen authoring; the modal exposes liquid colour, binding, motion and SFX controls.

UI audio import safely recontainers supported mono/stereo WAVEFORMATEXTENSIBLE PCM to a conventional PCM WAV when the existing native validator rejects the extended header. Samples are copied unchanged into a fresh project asset. Originals and Wicked's loader remain unchanged. Non-PCM GUIDs, bad chunk lengths, incompatible valid bits/channel masks/alignment and oversized inputs are rejected. The converter applies to UI sound import only.

## Scope and remaining checks

No GitHub push, CI, merge, release or independent gate approval. Debug, Vulkan, exported-game package playback, small-window modal layout and audible multi-instance sound mixing remain unverified. This release targets Windows DX12. Generic saved image/text/control hierarchies are supported; video, camera and hint-list hierarchies are rejected. Liquid SFX are portable; pre-existing button click-sound sidecars are outside this prefab implementation. Insertion currently also leaves an adopted standalone Screen asset in the receiving project's UI library; Undo removes the inserted hierarchy while imported assets remain. The liquid effect renders bottom-to-top; alternative ordinary Progress fill directions are outside its supported visual scope. Select an individual vial root when several liquid widgets share a common ancestor. Pre-existing Wicked dirt and root log.txt remain excluded.
