## Implementation and ownership
`EngineBridge/src/RiverWaterfallFlight.h` is a bounded flight/presentation model, separate from the prescribed-surface bed solver. Its CPU mesh fill makes no GPU calls. The proof explicitly calculates native normals/uploads at the graphics boundary. Incoming discharge and drop energy scale emitted effects; incoming gravity drives sheet travel. Constant sheet width and rounded toe remain presentation approximations, not a 3D fluid solver.

`Tests/RiverWaterfallProof.cpp` owns the disposable scene, connected WATER mesh, receiving oracle, native GPU transport and three persistent native emitter components. It reuses the accepted course shaders/artwork without changing them. It only solves the lower receiving reach in XZ; the falling sheet never enters that pressure projection. The proof adapts its raster dimensions to world bounds, retaining existing convergence, conservation, depth and speed checks.

Original procedural soft spray/mist sprites are generated by `Tools/prepare_waterfall_sprites.py` into `EngineBridge/assets/waterfall-v1`. No uploaded Unreal package, commercial texture or Blueprint code is copied. Fixture rocks reuse the existing owner model asset read-only. The fixture explicitly supplies a receiving reach/bed; it does not infer a receiver beneath every authored cliff.

The proof stages the reusable rock payload into a file-backed native archive before importing, so native resource streaming retains a real container to re-embed. The receiving oracle is hidden again after native spline regeneration on load to prevent a second coplanar water mesh. The fixture archive embeds native materials, scene entities and emitters, while sheet custom shader IDs/descriptors are masked and reconstructed after fresh load. This proves native fixture persistence. It is not the final authored-node schema or derived-resource lifetime policy for Studio.

## Reproduction
From the configured source checkout, use its existing VS18 Release generator:

```powershell
cmake --build BUILD/g6 --config Release --target RenegadeRiverWaterfallFlightTests RenegadeRiverWaterfallProof -j4
ctest --test-dir BUILD/g6 -C Release -R 'RenegadeRiver.*Tests' --output-on-failure
# Stage accepted Content/river and dxcompiler.dll beside the isolated proof first.
python Tools/prepare_waterfall_sprites.py BUILD/waterfall-g12a/Content/waterfall
# From BUILD/waterfall-g12a, supplying a real existing reusable rock asset:
./RenegadeRiverWaterfallProof.exe <evidence>/review <rock.rasset>
./RenegadeRiverWaterfallProof.exe <evidence>/reopen <rock.rasset> --reopen <evidence>/review/waterfall-native.wiscene
./RenegadeRiverWaterfallProof.exe <evidence>/small <rock.rasset> --height 1.1 --width 2
./RenegadeRiverWaterfallProof.exe <evidence>/rotated <rock.rasset> --heading .7
./RenegadeRiverWaterfallProof.exe <evidence>/interactive <rock.rasset> --interactive
```

Machine-specific invocation and source/binary hash manifest are retained in the BUILD evidence, not as committed absolute paths. Shader staging is manual for this isolated gate; Runtime packaging is not yet implemented.

## Failed attempts retained
Initial CPU sampling exposed sub-ULP duplicate travel at analytic joins; these samples are collapsed. The first correction used a line comment in a compact lambda and broke compilation; corrected to a block comment (`build-joins.log` retained). A later CPU mesh test exposed that native `ComputeNormals()` also uploads GPU data; the CPU mesh fill and proof graphics upload are now explicit separate steps (`cpu-bounds.exit` access violation retained, `cpu-final` passes).

The first512x256 receiving grid hit the bounded projection convergence check; the process also exited with an access violation on exception cleanup. Raster dimensions now follow world-space aspect ratio, and the GPU drain guard is established before configuration. Both failures remain in `gpu-first.log` and `gpu-first.exit`; the exception cleanup path has not been deliberately fault-injected again, so do not claim universal exception safety from the normal passing runs.

Fresh reopen initially lost textures despite correct foam/particle numbers. The memory-only imported rock payload left native resources with no durable container to reread during a second save. File-backed fixture staging fixes this without editing the source asset. A diagnostic attempt also dereferenced an invalid resource's texture and exited; diagnostics now guard validity. After texture restoration, the reopened receiving spline regenerated a visible native mesh and caused water z-fighting; explicitly hiding that oracle after load restores the single-sheet appearance. `gpu-textures`, `resource-reopen` and earlier grey captures are failure evidence, superseded by `resource-reopen-hidden` and `relocated-reopen`. Live review13376 was closed only to relink; final renamed review36268 remains open.

## Remaining gates and limits
Owner appearance review precedes G12B per the agreed plan. This proof does not yet detect arbitrary falls from author nodes, update terrain, move derived emitters with Undo/Redo, implement dry/nonreceiving ends, handle multiple linked falls, or integrate Test Game/Runtime/Build Game. Zero-flow source energy is CPU-verified; complete zero-flow GPU optics/emission behavior is not yet covered. Single native planar reflection remains an approximation on stacked surfaces. No original Wicked Editor parity or Unreal reference rendering has been performed.

Next: obtain appearance feedback from the open viewer, finish dry/zero-receiver coverage, then integrate accepted regions/effects through bridge services and the ordinary spline workflow. Follow with edit/history/lifetime/fresh reopen and actual Runtime/package regression checks. G12A/G12 release gates remain OPEN; independent exact-change review required by AGENTS has not occurred.
