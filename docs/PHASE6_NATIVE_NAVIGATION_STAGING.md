# Phase 6 Native Navigation — Staging

## Purpose

This staging branch establishes Renegade navigation on Wicked Engine's native
`VoxelGrid`, `PathQuery`, and `CharacterComponent::SetPathGoal` facilities.
Renegade does not introduce Recast/Detour, a second navmesh, or another actor
navigation world in Phase 6.

The long-term product direction remains deliberately open to a later surface
navmesh for high-quality ground-only AI. That would complement, not replace,
Wicked voxel navigation for flying, swimming, climbing, volumetric and dynamic
navigation use cases.

## Native Wicked baseline

The Renegade Wicked pin is `3a800b7134aafe58461093c8abb2e274d4e64033`.
At that pin:

- `wi::VoxelGrid` owns the generated occupancy grid and serializes through Wicked;
- `Scene::VoxelizeScene()` injects matching Scene geometry into a VoxelGrid;
- `wi::PathQuery::process()` performs pathfinding on that VoxelGrid;
- grounded PathQuery traverses occupied ground voxels with empty clearance above;
- flying PathQuery traverses empty voxels in full 3D;
- `CharacterComponent::SetPathGoal()` stores a goal and VoxelGrid pointer and
  defers native path processing to the normal Wicked Scene update.

Wicked's own character-controller example then reads the next native PathQuery
waypoint and drives `CharacterComponent::Turn()` / `Move()` toward it. Renegade
will follow that native split rather than pretending `SetPathGoal()` alone moves
an actor.

## Staging implementation

`NavigationService` is an EngineBridge adapter only. It currently provides:

1. bounded creator-facing grid generation settings;
2. creation of one persistent Scene entity carrying Wicked's serialized
   `VoxelGrid` component;
3. rebuild through `Scene::VoxelizeScene()` using navigation/collider filters;
4. synchronous start-to-goal `PathQuery` results for gameplay/services/tests;
5. native `CharacterComponent` path-goal handoff;
6. command-backed grid creation/rebuild for Undo/Redo and Studio dirty state; and
7. grounded and flying regression coverage on the same grid representation.

The default generation filter is:

`FILTER_NAVIGATION_MESH | FILTER_COLLIDER`

This follows Wicked's own character-controller navigation pattern and avoids
silently treating every decorative render mesh as walkable/navigation geometry.
Terrain generated by Wicked already carries the navigation-mesh filter.

## Creator authoring stage

The staging branch now also contains a Renegade-owned Navigation specialist
Inspector integrated into the Scene ADD menu and hierarchy selection routing.
The creator surface currently provides:

- **ADD -> NAVIGATION GRID** for a persistent native Wicked VoxelGrid entity;
- editable X/Y/Z resolution controls;
- a uniform voxel-size control in metres;
- **REBUILD GRID** using current terrain/navigation meshes and colliders;
- **FIT TO SCENE + REBUILD**, preserving a uniform voxel size and automatically
  increasing it when needed to remain within the bounded grid limits; and
- **SHOW NAVIGATION VOXELS**, using Wicked's own `VoxelGrid::debugdraw()` rather
  than a duplicate Renegade visualization.

Selecting an authored Navigation Grid in the hierarchy automatically reopens the
specialist Inspector. The ordinary Inspector remains hidden while this bounded
specialist surface owns the right panel, matching Audio and Particle authoring.

## Not implemented yet

The staging branch deliberately does not claim navigation completion. Remaining
work before a production PR includes:

- creator-facing navigation-agent / destination workflow;
- native next-waypoint following using `CharacterComponent::Turn()` / `Move()`;
- viewport debug display for an active queried path;
- Runtime/Lua path-query seams where needed by reusable actor behaviour;
- one visible actor path-following owner test in Test Level;
- save/reopen and packaged Runtime parity; and
- exact-head CI after the implementation is complete enough to justify a full
  Windows build.

## Acceptance direction

The first owner-visible acceptance should be intentionally small: generate a
navigation grid over a test scene containing terrain/floor plus an obstacle,
place or identify one Wicked Character actor, assign a destination, and confirm
that the actor follows a route around the obstacle in Test Level. A second proof
should demonstrate the same grid can support flying/3D path queries without
creating a separate navigation system.

Do not trigger repeated full CI while this remains a staging implementation.
